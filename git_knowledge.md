# Git Knowledge & Setup

## Git Installation
I installed Git on my system and verified the installation using:

```bash
git --version
```

This confirmed that Git is properly set up and ready to use.

## Git Client Choice

I decided to use GitHub Desktop as my primary Git client. I’m already familiar with the Git CLI, but GitHub Desktop makes it easier to visualize changes, manage commits, and handle branching without needing to remember every command.

Since I already use VS Code as my main IDE, I can also integrate Git operations there when needed, but GitHub Desktop feels more straightforward for managing repositories and resolving merge conflicts.

## Experience with Git

Yes, I have used Git before. I’ve mainly used it as a version control system for my own projects and also to contribute to public repositories.

In my workflow, Git helps me track changes, experiment safely using branches, and collaborate with others without overwriting work. It’s something I use regularly while working on development projects, especially when building features or fixing bugs.

## Interesting Things I Learned

One interesting thing I learned today is that GitHub has an inbuilt Kanban board. Previously, I used tools like Trello to manage tasks, but having a Kanban board directly inside GitHub makes it more convenient to track issues, features, and progress in the same place as the codebase.

This could make project management more streamlined, especially when working in a team environment.

## Reflection

Overall, setting up Git wasn’t new to me, but it reinforced how important version control is in real-world development. Using a combination of Git CLI, GitHub Desktop, and VS Code gives me flexibility depending on the task.

I think GitHub Desktop will be especially useful for quick commits, visual diff checking, and managing branches efficiently without breaking my flow.
