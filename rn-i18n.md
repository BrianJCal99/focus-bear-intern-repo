# Reflection

**How does react-i18next handle translations?**
From what I’ve learned, **react-i18next** works by connecting React components to translation files through a hook-based system. Instead of hardcoding text, you define keys (like `"welcome_message"`) and store the actual translations in separate JSON files for each language. The library then uses the `useTranslation` hook to dynamically fetch the correct string based on the currently selected language. It also supports features like interpolation (inserting dynamic values into strings), pluralisation, and fallback languages if a translation is missing. What stood out to me is how seamlessly it integrates into components - once set up, switching languages updates the UI instantly without needing to reload the app.

**What challenges arise when localising a React Native app?**
One of the biggest challenges is making sure the UI adapts properly to different languages. Some languages are much longer than others, which can break layouts or cause text overflow. Another issue is handling right-to-left (RTL) languages, which requires additional configuration and testing. I also found that managing translation files can become messy as the app grows, especially if keys aren’t well organised. There’s also the challenge of ensuring consistency in tone and meaning across languages, which often requires proper localisation rather than direct translation. Finally, debugging missing or incorrect translations can be tricky because errors don’t always show clearly in the UI.

**How would you test localisation support in an app?**
To test localisation, I would start by manually switching between languages and checking if all text updates correctly across different screens. I’d also test edge cases like longer translations to see if the layout holds up. Another important step is verifying fallback behaviour - if a translation is missing, the app should default to a base language instead of breaking. For automation, I would write tests to ensure the correct translation keys are rendered and not the raw keys themselves. I’d also test language persistence by restarting the app and confirming that the selected language is saved. Lastly, if the app supports RTL languages, I’d specifically test layout direction and alignment to make sure the UI behaves as expected.
